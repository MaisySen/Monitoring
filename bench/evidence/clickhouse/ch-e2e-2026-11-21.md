# ClickHouse storage path end-to-end, 2026-11-21 (run ch1)

Setup: ClickHouse 26.12.1.59 (official static build; product requires >= 24.8), server with
MONITORING_STORAGE=clickhouse, MONITORING_CLICKHOUSE_URL=http://127.0.0.1:8123, app data in its own
Postgres DB (chtest). Load: bench/scale/loadgen.js, 45 s, ~127 spans/s, 3 services, 5 hosts,
high-cardinality metric (100 customer ids). Fresh install: server auto-created the CH database and all
tables (spans, logs, metric_points, metric_series, span_stats + span_stats_mv) on first boot.

## Zero loss, exact counts (CH-side counts vs loadgen sent counters)
- spans:  5,720 sent / 5,720 stored (monitoring.spans)
- logs:     924 sent / 924 stored (monitoring.logs)
- metric points: 620 sent / 620 stored for sent metrics (scale.orders.placed 500 + loadgen host metrics 120)
  - monitoring.metric_points holds 7,013 rows total; the extra rows are server-generated, not intake
    duplication: trace.http.server.request.* (2,081 x 3) are span-derived request metrics produced at
    intake (artifacts/api-server/src/intake/otlp.ts), and system.load.*/system.mem.* rows come from the
    synthetic host sampler (artifacts/api-server/src/jobs/sample.ts). Sent-metric rows match exactly.
- Intake errors: 0 of 368 requests.

## APM rollups (span_stats_mv, materialized view on is_top_level spans)
- sum(hits) per (bucket, service) equals stored is_top_level span counts exactly for all 6
  (bucket, service) pairs: 378/378, 363/363, 403/403, 507/507, 551/551, 500/500.
- Note: a naive probe against parent_id='0' (900) reads as 3x inflation; that is the wrong root
  definition. is_top_level = server/producer kind, cross-service parent, or parentless
  (intake/otlp.ts:326-336), so one trace contributes one top-level span per service it touches.

## Read paths served from ClickHouse (UI APIs, all verified with data)
- GET  /api/ui/apm/services            service list with hits/errors/latency percentiles
- POST /api/ui/apm/spans               span search with filter service:svc-00 status:error
- GET  /api/ui/apm/traces/:traceId     full trace waterfall payload
- POST /api/ui/logs/search             log search with service filter
- POST /api/ui/metrics/query           timeseries query avg:scale.orders.placed{*} with 10 s buckets

Caveats: single-node MergeTree (no cluster/replication), 45 s moderate-load run, no CH restart or
backfill scenario covered here.
